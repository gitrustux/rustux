rpg - Rustica's package tool

USAGE
    rpg [--root DIR] COMMAND ...

    update                       get the sources' package lists (signatures checked)
    upgrade [-y]                 upgrade what a source has newer versions of
    install [-y] NAME|./FILE.rpg...   install packages, with what they need
    remove [--purge] NAME...     remove packages (--purge: their configuration files too)
    autoremove [-y]              remove packages installed for others, no longer needed
    search WORD... [--names-only]
    show NAME | ./FILE.rpg       a package's fields
    policy [NAME...]             installed and candidate versions, and where from
    list [--installed|--upgradable|--held|--apps] [--json]
    depends NAME | rdepends NAME
    hold NAME... | unhold NAME...
    download NAME...             a package file into the current folder
    clean                        empty the download cache
    source list | add [apps] URL SUITE SECTION... | remove N
    key list | add [--apps] FILE [NAME] | remove ID
    files NAME | owner PATH... | verify [NAME...]
    boot list | boot status | boot update
                                 the system images, how each one started;
                                 write rboot's entries
    fix                          finish an install a power cut or crash interrupted
    build DIR [-o FILE] | info ./FILE.rpg
    index REPO [--suite S] [--section S] [--arch A]   (publishing)
    index --apps REPO [--platform N]                   (an apps repository)
    version

    rpg is Rustica's one package tool: what Debian splits between dpkg
    and apt. Changes are root's (sudo rpg ...); anyone may look and
    search. -y answers yes to the question; without it, no answer (a
    script) is no.

PACKAGES
    A .rpg file is a gzipped tar: control (the package's fields), files
    (each file's SHA-256, mode and owner), scripts/postinst,
    scripts/prerm and scripts/postrm (optional) and data/ (the files,
    rooted at /). The file name is NAME_VERSION_ARCH.rpg.

    rpg build DIR makes one from DIR/RPG/control, the optional scripts
    DIR/RPG/postinst, prerm and postrm, and every other file under DIR
    (DIR/usr/bin/x becomes /usr/bin/x). Everything belongs to root; the
    modes are the files' own. The control file:

        Package: hello
        Version: 1.0-1
        Architecture: x86_64        (or all, aarch64)
        Depends: rustica-base (>= 0.1), foo | bar
        Conflicts: ...
        Provides: ...
        Maintainer: ...
        Description: a one-line summary
         Longer text, each line starting with a space.

    Versions compare as Debian's: 1.10 > 1.9, 1.0~rc1 < 1.0, 1.0-2 >
    1.0-1, an epoch first (2:0.1 > 1.9).

INSTALLING
    rpg install ./FILE.rpg checks the package (every file's SHA-256), its
    dependencies and conflicts, and that no file belongs to another
    package; then writes the new files beside their places, and renames
    each over the old one. An upgrade removes the files the new version
    no longer has. postinst runs with "install", or "upgrade OLD-VERSION";
    prerm before removing and postrm after, with "remove".

    On Rustux /bin, /usr and /boot are the boot image, read-only:
    packages install into /opt, /etc, /var and the like, and the system
    image onto the EFI partition (/boot/efi); a package with files in the
    boot image is refused, nothing changed.

    Configuration files (everything in /etc) are yours: one changed since
    its package installed it is never overwritten; the package's new one
    goes beside it as FILE.rpg-new. rpg remove keeps them; rpg remove
    --purge (also later, for a removed package) deletes them.

    A power cut or crash in the middle is safe: before anything changes
    the plan is written to /var/lib/rpg/journal and pending/. rpg fix
    (and the next rpg install or remove) finishes it, or, if the new
    files were not all written yet, undoes it and the old version stays.

REPOSITORIES
    /etc/rpg/sources.list (and sources.list.d/*.list) has a line per
    repository: URL SUITE SECTION..., such as

        https://rustux.com/download/rustica  redfox  main

    rpg update fetches each one's dists/SUITE/Release and Release.sig,
    and takes it only if a key in /etc/rpg/keys signed it; then the
    indexes, whose SHA-256s Release gives. A source that fails keeps the
    lists it had. A downloaded package must have the SHA-256 the index
    gives. A private repository's CA certificate goes in
    /etc/rpg/ca-certificates.pem.

    rpg install NAME takes the highest version any source has, and the
    packages it needs (marked as installed for it: rpg autoremove removes
    them once nothing needs them). rpg upgrade upgrades everything it
    can; a held package (rpg hold) and an upgrade that does not fit are
    kept back.

    Publishing: put the packages under REPO/pool (rpg pool-path FILE
    says where), run rpg index REPO, then sign:

        openssl pkeyutl -sign -inkey KEY.pem -rawin \
            -in REPO/dists/redfox/Release -out REPO/dists/redfox/Release.sig

APPS
    An app (Kind: app; FoxDen, docs/FOXDEN.md) lives in /apps/ID alone,
    ID its reverse-DNS name (org.rustica.calculator), described by
    /apps/ID/manifest (Id, Name, Summary, Exec, Icon, Categories,
    Permissions, Platform). rpg build DIR makes one from DIR/RPG/control
    and DIR as the app's folder. rpg refuses an app with files elsewhere,
    scripts, set-user bits, links out of its folder, relations to other
    packages, or a platform level newer than this system's (1). rpg list
    --apps lists them; Applications starts them in their sandbox (man
    appctl). rpg remove --purge also removes the users' data for it
    (~/.local/share/apps/ID, ~/.config/apps/ID, ~/.cache/apps/ID).

    Apps come from app sources, lines starting with "apps":

        apps https://rustux.com/download/apps  platform 1

    laid out by platform level, not release: platform/1/Release (signed),
    platform/1/x86_64/Apps.gz (each app's fields with its name, summary,
    categories, permissions and icon), pool/L/ID/, media/ID/. An app
    source must be signed by a key in /etc/rpg/keys/apps (rpg key add
    --apps), never an archive key, and an archive key is never trusted
    for apps: a system repository's apps and an app source's system
    packages are refused, the second refusing the whole source. Then
    rpg search, install, upgrade and remove work for apps as for any
    package, by ID; rpg install shows what an app asks for before it
    installs it. Package files (rpg install ./FILE.rpg) still work.

    Publishing an apps repository: the app packages under REPO/pool (rpg
    pool-path FILE says where), rpg index --apps REPO, then sign
    REPO/platform/1/Release with the apps key; scripts/publish-apps.sh
    does all of it.

THE SYSTEM
    The system is image-based: the kernel file carries every program
    (/bin and /usr, read-only), so the system is a few packages:

        rustica-system-VERSION   /boot/efi/EFI/Rustica/rustux-VERSION.efi
        rustica-system           the newest: depends on the one above
        rboot                    the boot manager
        rustica-server           the edition: the text login by default
        rustica-desktop          or the graphical login (they conflict)

    rpg upgrade installs a new image beside the old one: the new one
    starts next, the previous one stays in rboot's menu. Two images are
    kept: after an install or upgrade the others go, but never the one
    running (rpg autoremove leaves images alone); sudo rpg remove
    rustica-system-VERSION removes one. sudo rpg install rustica-desktop
    switches the edition (Replaces: the other, which goes first).

    A new image is tried three times before it is trusted: its entries
    are written as rustica+3.conf; rboot counts each try (rustica+2-1.conf)
    and a boot that reaches its target removes the count (init's
    boot-complete unit runs bootctl bless). An image that used its tries
    without getting there failed: rboot starts the previous one instead.
    Every entry has panic=10, so a kernel that panics restarts by itself.
    rpg boot status says which image runs and how each one did.

    rpg boot update (the image and edition packages run it) writes
    rboot's entries in /boot/efi/loader/entries: rustica.conf (the newest
    image), rustica-desktop.conf (the desktop edition's, the default) and
    rustica-VERSION.conf for each older image, "(previous)". Their
    command line is /etc/rustica/boot.conf's "options ..." line; the
    edition is /var/lib/rustica/edition. Entries it wrote say so on their
    first line: changes to them are lost. rpg boot list shows the images.
    RPG_ESP=DIR puts /boot/efi at DIR (with --root: the installer mounts
    the new system's EFI partition beside it).

FILES
    /etc/rpg/sources.list        where packages come from
    /etc/rpg/keys/*.pub          the keys trusted to sign them
    /etc/rpg/keys/apps/*.pub     the keys trusted to sign app sources
    /var/lib/rpg/lists/          the sources' package lists (rpg update)
    /var/cache/rpg/archives/     downloaded packages (rpg clean)
    /var/lib/rpg/status          the installed packages
    /var/lib/rpg/info/NAME.files what each one installed
    /var/lib/rpg/journal         an operation in progress
    /etc/rustica/boot.conf       the system's command line (rpg boot update)

EXAMPLES
    sudo rpg update
    sudo rpg upgrade
    rpg search editor
    sudo rpg install hello
    rpg build hello                     (makes hello_1.0-1_all.rpg)
    sudo rpg install ./hello_1.0-1_all.rpg
    rpg owner /etc/hello.conf
    rpg verify
    rpg boot list
    sudo rpg remove --purge hello
    rpg search calculator
    sudo rpg install org.rustica.calculator   (an app, from the apps source)
    rpg list --apps
