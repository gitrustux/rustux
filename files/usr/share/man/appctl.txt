appctl - start an app in its sandbox

USAGE
    appctl run ID [ARG...]
    appctl open ID FILE...
    appctl view ID [FILE...]
    appctl run|open|view|permissions --dir DIR ...
    appctl permissions ID

    An app (an rpg package of Kind: app, in /apps/ID) runs sandboxed:
    Applications starts it with appctl run. It sees a root of its own
    (docs/FS.md, Views) and runs in a job whose policy refuses the calls
    that reach the system without a handle (docs/SYSCALL.md,
    JOB_SET_POLICY).

    run          start the manifest's Exec (with ARGs after its own), wait
                 for it, and exit with its code. Its data folders are made
                 if new; it starts in the first, with HOME, USER, APP_ID,
                 XDG_DATA_HOME, XDG_CONFIG_HOME, XDG_CACHE_HOME, TMPDIR,
                 PATH=/apps/ID/bin and the scale (RUSTICA_SCALE, from
                 ~/.config/rustica.conf)
    open         as run, with each FILE in its view at its own path (rw
                 if you may write it, else ro), the paths its arguments:
                 what Files does to open a file with an app whose manifest
                 lists its type (Types: txt md). Its folder shows that file
                 alone. Folders, missing files and paths with . or .. are
                 refused; 24 files at most
    view         the paths it sees, one per line: ro, rw or open, then the
                 path (with FILEs: as open would give them)
    permissions  what it asks for and what it gets

WHAT AN APP SEES
    ro    /apps/ID, /usr, /etc/passwd, group, timezone, localtime,
          os-release, hostname
    rw    ~/.local/share/apps/ID, ~/.config/apps/ID, ~/.cache/apps/ID
    open  /dev/null, /dev/zero, /svc/window, /svc/log

    and with its permissions:

    network           open /svc/netsock; ro /etc/resolv.conf, /etc/hosts
    files:documents   rw ~/Documents (files:pictures ~/Pictures,
                      files:music ~/Music, files:videos ~/Videos,
                      files:downloads ~/Downloads)
    files:home        rw the whole home
    removable         rw /media
    audio, camera, location
                      nothing yet (no services for them)
    system            not given: only apps from the system's own sources
                      (FoxDen step FD3) will have it

THE FILE CHOOSER
    While the app runs, appctl is its file chooser (<rustux/portal.h>:
    rx_portal_open, rx_portal_save): on the app's request it shows
    chooser, a window of the session's ("NAME wants to open a file"),
    opens the file the user picks as the user (read only, or written
    from empty for save) and hands the app that file alone. Cancel: the
    app gets nothing. An app without files: permissions reaches the
    user's files this way only.

FILES
    /apps/ID/manifest            Exec and Permissions (docs/FOXDEN.md)
    ~/.config/apps/permissions   narrows them: lines "ID: PERMISSION...",
                                 "ID: -" for none; an app gets at most
                                 what its manifest asks for

DEVELOPER MODE
    --dir DIR instead of an ID: the app in DIR (its manifest and its
    program, as rpg build takes it), not installed, in the same sandbox as
    when it is installed, for you alone; DIR is in its view read only, at
    its own path. No password is needed: nothing is installed. Nobody has
    checked it: it is yours.

EXAMPLES
    appctl run org.rustica.example
    appctl view org.rustica.example
    appctl open org.rustica.texteditor ~/Documents/notes.txt
    appctl run --dir ~/src/myapp/build
    echo "org.rustica.example: -" >> ~/.config/apps/permissions
